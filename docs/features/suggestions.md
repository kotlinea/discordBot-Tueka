# Suggestions

メンバーからアイデアや改善案を受け付け、専用チャンネルで投票と審査を行います。投稿者は`/suggest`を実行し、本人にだけ表示されるフォームへ回答します。回答内容はBotがボタン付きEmbedへ変換します。

## 必要な権限

Botには投稿先チャンネルのView Channel、Send Messages、Embed Linksが必要です。審査担当者は、設定した審査ロールまたはManage Messages権限を持つ必要があります。

## 設定する

1. ダッシュボードで「エンゲージメント」から「Suggestions」を開きます。
2. 提案の投稿チャンネルを選択します。
3. 承認・却下・審査中への変更を許可するロールを選択します。
4. 投稿フォームを1～5項目で構成します。各項目は1行／複数行、必須／任意、最大文字数を指定できます。
5. 必要に応じてメンバー投票、投稿者表示、審査ログチャンネルを設定します。
6. 「変更を保存」で有効化します。

保存時にチャンネルとロールが同じDiscordサーバーに存在するか、Botに必要な権限があるかを再検証します。別画面で更新されていた場合は409となるため、再読み込みしてから変更をやり直してください。

## 投稿と投票

`/suggest`を実行すると、設定済みのModalがコマンド実行者だけに表示されます。送信後、専用チャンネルへ「審査待ち」のEmbedが投稿され、投稿者には提案番号が非公開応答で返ります。

入力中に投稿フォームが変更された場合は、`/suggest`を実行し直して回答してください。

投票を有効にすると「賛成」「反対」を選択できます。同じ選択肢をもう一度押すと票を取り消し、反対側を押すと票を変更します。承認または却下後は投票できません。

## 審査する

審査担当者はEmbed上のボタンを押し、1～1000文字の理由を入力して状態を変更します。Dashboardではサーバー管理者が「最近の提案」から理由を入力し、審査・履歴確認を行えます。別の担当者が更新した場合は、再読み込みして状態を確認してください。

| 状態 | 用途 |
| --- | --- |
| 審査待ち | 投稿直後の状態 |
| 審査中 | 担当者が内容を確認している状態 |
| 承認済み | 採用する提案。投票を停止 |
| 実装済み | 承認した提案を実施した状態。承認済みから変更 |
| 却下 | 採用しない提案。投票を停止 |

状態を変更した担当者、時刻、理由をDashboardの「履歴」で確認できます。審査ログチャンネルを設定した場合は、実装済みへの変更を含め、結果と理由も送信されます。ログ送信に失敗しても提案の状態変更は取り消されません。

## Discussion

「Discussionスレッドを作成」を有効にすると、新しい提案の投稿にDiscussionスレッドが作られます。Botには追加でCreate Public Threads、Send Messages in Threads、Read Message Historyが必要です。作成後は提案のEmbedとDashboardからスレッドを開けます。無効時は新しいスレッドを作成しません。

## ロードマップ・分類・重複統合

管理者は機能内の「提案ロードマップ」で、読み込んだ提案を状態別に確認します。カテゴリー・タグ・状態のフィルターはサーバーで適用され、1ページ50件ずつ以前の提案も読めます。提案を開くと、分類、理由付き審査、重複統合、履歴を操作できます。編集中は他の操作やフィルターを止め、保存失敗時も入力を残します。

受付設定の`categories`は20件、`tags`は50件まで。名前は改行を含まない1〜40文字です。提案にはカテゴリー1件とタグ10件までを付けます。選択肢の削除・名前変更で既存の分類を書き換えることはありません。分類を保存し直すときは登録済みの名前を選びます。

「重複提案を統合」で統合先の番号を確認し、理由を入力して保存します。元投稿、原票、Discussion、審査履歴は残ります。元提案の投票は閉じ、統合先への参照を表示します。統合先は同じサーバーの未統合の提案で、実装済みへの重複統合もできます。自分自身、期限切れ、投稿失敗中の統合先は指定できません。1つの統合先につき元提案100件までです。別の管理者がどちらかを更新した場合は、確認からやり直します。

同じ人の票は1票として数えます。統合先の票があればそれを優先し、なければ元提案の最新の票を使います。統合先で票を取り消しても原票は保存し、過去の票が復活しないようにします。統合済みのグループを別の提案へ統合すると、配下の参照も同じ統合先へ移し、その履歴を残します。

## 保存期限と復旧

新規投稿の`retention_days`は1〜365日、既定30日です。提出時の保存日数を固定し、期限後は本文・投票・履歴・配送記録を削除します。機能OFFも削除対象で、Bot停止中は次の起動で物理削除します。期限を過ぎた提案は読む操作でも返しません。保存期限のない既存の記録には、日数を設定しても自動適用しません。

DBとバックアップには回答本文が含まれます。秘密情報を入力しないでください。Discordの元投稿やDiscussionはDBの期限削除では消えません。必要なDiscord側の整理は管理者が別に行います。共通バックアップ・復旧を使うと、分類・統合先・元の投票・履歴も同じ時点へ戻ります。

フォーム回答、投稿者、投票、状態変更履歴が保存されます。Bot再起動後も投稿済みの提案ボタンを利用できます。

受付後に「投稿を待っています」と表示された場合は、提案番号を控えて投稿を待ちます。投稿失敗が続く場合は、管理者が投稿先とBot権限を確認し、提案番号を運用者へ伝えてください。再投稿する前に、投稿先と処理状態を照合して重複を防ぎます。機能を無効化すると新規投稿と既存ボタン操作を停止し、保存期限内の提案と履歴を保持します。
