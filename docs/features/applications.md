# 申請フォーム

Staff応募、認証、提携、イベント参加などの申請をフォームで受け付けます。回答は申請者へのDiscord応答と管理者の審査画面で扱い、一般チャンネルへ投稿しません。

## 管理者が準備する

サーバー運営の「申請フォーム」でフォーム名と設問を入力し、保存します。設問は1〜5個、短文または段落を選べます。項目キーは英小文字から始まる40文字以内の英小文字・数字・アンダースコアで、フォーム内で重複できません。質問は45文字、回答は最大4000文字です。必須・任意と最小/最大文字数を指定します。

必要なロールはいずれかを持つメンバーが対象です。拒否ロールは許可より優先します。未選択ならロールによる制限なし。アカウント作成日数・参加日数、再申請までの秒数も設定できます。サーバー内のロール一覧から選択します。消失した選択済みロールはID付きで表示するため、修正してから保存してください。

フォームの受付と「受付全体の設定」の両方を有効にしてください。フォームはサーバーごとに100件までです。作成や審査にはサーバー管理権限が必要です。

## メンバーが回答する

Discordで `/apply` を実行し、受付中のフォームを選んで回答します。受付条件は提出時の最新ロールと参加状況で確認します。フォームが変更された場合は開き直してください。同じフォームに未審査・審査中の申請がある間は追加提出できません。再送された同じ受付は二重保存しません。

`/application-status` は自分の直近10件の保存期限内の申請を本人だけに表示します。取り下げる場合は `withdraw_id` に申請番号を指定します。審査が終わった申請は取り下げられません。

## 審査する

「申請の審査」で提出時点の設問と回答を読み、理由を入力して審査中・承認・却下を選びます。自分の申請は別の管理者に審査してもらってください。理由、審査者、履歴を保存します。承認・却下・取り下げ後は終端となり、再審査できません。複数管理者の競合では入力を残して更新を拒否します。理由を破棄して最新状態を確認してください。

## 保存期限・無効化・復旧

回答と申請履歴の保存期限は提出時に確定します。既定30日、1〜365日です。期限が過ぎた申請は一覧に表示せず、Botが毎分最大500件ずつ回答・履歴を削除します。Bot停止中の削除は再開後に行います。フォーム定義と設定変更の監査は残ります。保存済みのバックアップは別の保存期限で管理してください。DBとバックアップを読める運用者も回答へアクセスできるため、パスワードや認証情報の入力には使わないでください。

フォームをOFFにすると新規回答を停止します。受付全体をOFFにすると新規回答と審査・取り下げを停止し、既存の回答と履歴は保存期限まで管理者が読めます。期限削除はOFFでも継続します。

申請・フォーム・履歴はTuekaの共通DBバックアップに含まれます。復旧は対応するImageとDBのSnapshotを組にして行ってください。処理直後に応答が届かなかった場合は、まず `/application-status` で保存状態を確認します。
