# 予約メッセージ・イベント

サーバー管理者はDashboardの「予約メッセージ・イベント」で、チャンネルへのEmbed投稿とDiscordイベントの作成を予約できます。「予約設定」で機能を有効にしてから保存します。

## 予約する

種類、タイトル、本文、実行日時を入力します。日時は端末のタイムゾーンで入力し、サーバーにはUTCで保存します。30秒以上先、365日以内の日時を指定してください。タイトルは100文字、本文は2000文字までです。

メッセージはサーバー内のテキストチャンネルを選び、Embedの色を設定します。Botには投稿先の「チャンネルを見る」「メッセージ履歴を読む」「メッセージを送信」「埋め込みリンク」が必要です。メンションは通知しません。1回、24時間ごと、7日ごとを選び、最大365回・最終日時が365日以内になるよう指定します。繰り返しは固定間隔なので、夏時間のある地域では端末表示時刻が変わることがあります。予約中の上限はサーバーごとに100件です。

イベントでは、Discord上に作成する日時と、イベントの開始・終了日時、場所を入力します。外部の場所を使うイベントを作成します。開始は作成予定の60秒以上後、終了は開始の60秒以上後から7日以内にします。Botには「イベントの管理」が必要です。イベントは1回だけ作成します。

Discordイベントの説明は照合用の識別子を含めて1000文字以内です。長い本文はイベント上で末尾を「…」に省略し、予約に保存した本文はそのまま残ります。

## 編集・取消・履歴

一覧から配送と監査履歴を開きます。最初の配送予約前は内容を編集できます。別の管理者が更新した場合は再読み込みして確認し、保存失敗時に残った入力を調整してください。

「今後の配送を取り消す」は未送信の配送と以降の予約を取り消します。既に投稿したメッセージ・作成したイベントは残ります。送信開始済みで結果を確認できない場合は取消が保留されるため、配送履歴を確認してください。

予約処理済みは、すべての回が配送待ちになったか期限超過になった状態です。実際の投稿結果は配送履歴で確認します。配送の遅延は予定から10分まで許容し、それを過ぎた未送信の回は飛ばします。停止からの再開時に過去の投稿をまとめて送ることはありません。

通信結果が不明なときは、Botが投稿した直近200件のメッセージ、またはDiscordイベント一覧から受領を照合します。見つからない場合も同じ内容を新規送信せず、失敗として残します。「失敗した配送を再確認」は同じ配送記録を再処理します。期限後の未送信記録は再送できません。削除済みの受領や古いメッセージは自動照合できないことがあります。

## 無効化・保存期限・復旧

機能を無効にすると新規予約・編集・取消・配送を停止します。再開時も期限を過ぎた回は飛ばします。既に送信を開始したDiscord操作は完了することがあります。

保存日数は1〜365日、既定30日です。作成時の日数を予約ごとに記録し、最終実行予定日時からその日数を過ぎると本文・履歴・配送記録を削除します。取消時は取消日時から数えます。無効中も保守処理は削除し、Bot停止中は次の起動で削除します。期限を過ぎた記録は画面に表示しません。

本文はDBとバックアップに含まれます。秘密情報を入力しないでください。共通バックアップ・復旧を使い、DBを含む同じ時点のデータを復旧してください。復旧後も送信開始済みの記録は受領照合から再開します。
