# 異議申立て・ModMail

自分への処置に異議を申し立てたり、管理者へ非公開で問い合わせたりできます。本文・返信・審査履歴は本人とサーバー管理者だけが確認できます。一般チャンネルには投稿しません。

## 本人の操作

- `/appeal guild_id:サーバーID case_id:Case番号` で本人のCaseへ異議を申し立てます。サーバーから退出・削除された後も、BotのDMから利用できます。Caseの本人以外は受け付けません。
- `/modmail guild_id:サーバーID` で問い合わせを作成します。送信時に現在のサーバー所属を確認します。
- 関連する自分の申請がある場合は、任意の `application_id` を指定できます。別人・別サーバー・期限切れの申請は関連付けられません。
- `/appeal-status` は自分の一覧、やり取り番号の指定で本文と返信を確認します。DMが届かない場合も照会できます。
- `/appeal-reply` で未解決のやり取りに返信し、`/appeal-withdraw` で取り下げます。

本文は1〜2000文字、会話は100メッセージまでです。同じ本人・Caseの未解決案件と、本人の未解決ModMailはそれぞれ1件。新しい受付には60秒の間隔が必要です。パスワード、Token、認証コードなどを入力しないでください。

## 管理者の審査

Dashboardの「異議申立て・ModMail」で内容を開き、返信や審査理由を入力します。返信と審査結果は保存と同時にDM配送を予約します。本人と元の処置担当者は異議申立てを審査できません。別の管理者が担当してください。

「審査中」「承認」「却下」「完了」へ変更でき、理由・担当者・日時を履歴に残します。承認は再審査の判断です。Timeout解除・Unbanなどの処置はModerationで別途実行し、その監査を確認してください。

同じ本人のTicket番号を関連付け、サポート画面へ移動できます。既存Ticketの閲覧権限は引き継がれ、関連付けだけで権限は増えません。申請やCaseへの参照には元の画面の権限・保存期限が適用されます。

保存中は操作を抑止し、競合時は入力を保持します。最新の内容を読み直してから再実行してください。

## DM配送と保存

DM拒否などの失敗は配送欄で確認します。再試行は同じ配送記録を使います。送信結果不明の場合は直近200件のDMから受領記録を照合し、見つからなければ自動で再送しません。本人は `/appeal-status` から保存済みの返信を確認できます。

受付をOFFにすると新規受付・返信・審査・配送を停止し、既存データは保持します。期限内の本人照会と管理者閲覧は継続できます。保存日数は1〜365日、既定30日で、受付時の期限を使います。OFFのサーバーもBotの期限削除対象で、Bot停止中は次回起動後に削除を再開します。期限切れの本文と履歴は照会できません。

DBバックアップには本文・返信・履歴と配送記録が含まれます。DB内の本文は平文のため、運用者はDBとバックアップの閲覧権限を制限してください。復旧後の送信結果不明なDMも受領記録を照合します。
