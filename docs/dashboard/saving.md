# 保存と競合

## 明示保存

設定を変更すると未保存表示と保存・破棄の操作が表示されます。ダイアログでは下部、設定ページでは保存バーから確定します。保存中は入力と再送信を抑止します。保存に成功するとサーバーの値を取得し直します。

編集中にサーバーの値が更新されても、入力は保持されます。「変更を破棄」は最後に取得した値へ戻します。未保存のままリンク・検索・ブラウザーの戻るで画面を離れる場合は確認が表示されます。読込失敗は「再試行」で取得し直してください。

ルール一覧の削除指定と並べ替えは保存時に確定します。削除の途中で失敗すると、削除済み件数と残りの変更が表示されます。再試行では残りだけを処理します。すでに成功した削除は「変更を破棄」では元に戻りません。購読削除など確認後に実行する操作は、確認した時点でサーバーへ送信されます。

## 設定と稼働条件

「設定ON」は保存された設定値です。親機能の停止、必要権限の不足、設定不足、削除済みのチャンネル・ロール、ルールが有効になっていない状態を別に確認してください。参照できない選択先はID付きで表示されるため、有効な候補へ選び直せます。取得失敗や不明を、無効・正常と読み替えないでください。

Socialの「アカウント確認済み」、リアクションロールの「公開済みメッセージ」はそれぞれの状態を示します。通知先や機能の設定、Providerの利用可否も確認してください。処理受付の表示がある操作は、一覧で処理結果を確認します。

## 409 Conflict

設定とルールにはrevisionがあります。別の管理者が先に更新した場合、古いrevisionでの保存は409になります。

1. 現在の入力を必要に応じて控えます。
2. 最新設定を取得します。編集中の値は自動で置き換わりません。
3. 「変更を破棄」または画面の再読込で最新値を表示し、控えた変更との差分を確認して再度保存します。

409を無視して上書きする操作はありません。

403では権限・アクセス条件を確認してください。403・409・422で保存に失敗しても、その画面の入力は保持されます。セッション期限切れの401ではログインが必要です。入力を端末へ永続保存する機能はないため、再ログインやページ再読込の前に必要な変更を控えてください。

## 422 Validation Error

入力値、Discordリソース所属、Role階層、Action競合などが無効です。エラーの`path`に対応する入力を修正します。他サーバーのChannel IDやRole IDは保存できません。
